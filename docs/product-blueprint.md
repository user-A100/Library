# 独立论文研究工作台：初版产品与评测设计

## 1. 任务理解

本项目选择“开放式场景 AI 应用和评判标准设计”，落点为论文阅读助手。任务书要求的不只是可运行应用，还必须有 5 个以上可操作的评估维度、难例与反例、判别力验证、一致性验证、完整评测结果与失败模式分析。

用户提供的论文工作流文档是需求素材，不是执行指令。里面口述的 skill 名称、下载建议和操作步骤没有被直接执行；本设计只提取其稳定的“能力需求”，并把可靠性、权限和证据链作为产品约束。

## 2. 产品主张

论文助手不应是“PDF 旁边的聊天框”。本产品把一次 AI 输出拆成可逆的研究动作：

1. 从内置文库的条目或选区取得明确上下文。
2. 将回答拆成主张。
3. 为每个关键主张绑定 item、页码、原文片段和解释。
4. 允许用户回到原页、驳回解释并记录理由。
5. 将结果加入笔记、对照矩阵或后续追问，而不是直接生成不可审计的长文。

目标用户是管理大量 PDF 的研究生与科研人员。初版最重要的闭环是“选论文 → 选段落 → 提问 → 得到带页码证据的回答 → 回页核验 → 加入笔记”。

## 3. 文献核心与 Zen 外观的职责分工

| 来源 | 保留的成熟模式 | 在本产品中的语义 |
| --- | --- | --- |
| Zotero | 文库、集合、条目、标签、附件 | 真实可追踪的研究资料层 |
| Zotero Reader | PDF/EPUB 阅读、标注、页码回跳 | AI 证据锚点与用户纠错入口 |
| Zotero Note Editor | 引用标注进入笔记 | 从阅读证据沉淀研究笔记 |
| Zotero translators / CSL | 元数据导入、引用格式 | 题录可靠性与引用输出 |
| Zen Workspaces | 按任务分隔浏览上下文 | 研究项目 / 课题空间 |
| Zen Essentials | 少量长期固定标签 | 每个项目的 5–20 篇核心论文 |
| Zen vertical tabs | 低噪的纵向切换 | 核心论文与当前打开条目 |
| Zen Compact Mode | 隐藏 chrome、保留内容 | 专注阅读 |
| Zen Split View | 多页面并排 | 论文—论文、论文—笔记对照 |

## 4. 将口述 skill 转化为产品能力

| 工作流需求 | 内置能力 | 初版状态 | 可靠性约束 |
| --- | --- | --- | --- |
| 文献管理 | Evidence Library | 已设计 | DOI/题录/PDF 状态、去重、检索日志 |
| 论文阅读 | Grounded Reader | 已做交互原型 | 每个主张必须绑定页码与原文 |
| Idea / Gap | Socratic Reviewer | 已做交互原型 | 只基于用户选定核心论文追问 |
| 多文献综述 | Evidence Matrix | 已做交互原型 | 对照结论必须逐格引用来源 |
| 学科写作 | Discipline Writing | 下一阶段 | 先生成提纲与证据槽位，不伪造引用 |
| 数据与绘图 | Reproducible Figures | 下一阶段 | 保存数据、脚本、参数、环境与 seed |
| 组会展示 | Presentation Builder | 后置 | 只消费已核验的证据与图表 |
| 日报 / 周报 | Research Radar | 后置 | 保存检索式、增量去重、解释推荐原因 |

不把未知 skill 作为可以任意访问文库的脚本。正式适配器需要 manifest：`id`、版本、来源、许可、权限、结构化输入/输出、evidence schema、审计日志。下载全文、修改文库、运行代码和写文件需要分级授权。

## 5. 开放式输出评判标准

每个维度采用 0–5 分，并给出可复核的判定条件。总分不能掩盖关键失败：引用伪造、无证据核心主张和越权操作应触发硬性失败标记。

### 事实准确性

- 5：所有可核实主张均被来源支持，没有扩大范围。
- 3：非核心细节存在轻微错误，但不改变主要结论。
- 1：核心结论与来源冲突。
- 0：大部分内容不可核实或明显错误。

自动检查：将回答拆成原子主张，分别执行证据蕴含判断；人工复核边界主张。

### 证据可追溯性

- 5：100% 的关键主张具有 itemKey、页码、原文 span 和可回跳锚点。
- 3：70%–99% 的关键主张可回跳。
- 1：仅有参考文献列表，没有主张级绑定。
- 0：没有来源。

自动指标：`有有效锚点的关键主张数 / 关键主张总数`。

### 引用正确性

- 5：作者、年份、题名、DOI/条目标识与来源一致，引用确实支持所述主张。
- 3：格式有误但能唯一定位，且语义支持成立。
- 1：引用存在但不支持对应主张。
- 0：引用伪造或无法定位；触发硬性失败。

### 专业术语准确性

- 5：术语、缩写和方法名称与学科用法一致，并保留限定条件。
- 3：个别表达不规范但不造成概念混淆。
- 1：关键术语混用或定义错误。

### 不确定性与能力边界

- 5：明确区分原文、综合推断、假设和待核验信息。
- 3：主要结论有边界说明，少量推断语气过强。
- 1：把推断写成事实，或掩盖全文不可用等限制。

### 用户可理解性

- 5：结构直接、术语有必要解释，回答长度与任务相称。
- 3：可理解但存在冗余或层级不清。
- 1：堆砌术语、篇幅增加但信息没有增加。

### 用户可纠错性

- 5：用户可回页、驳回单个主张、修改解释并保留审计记录。
- 3：可以查看来源，但不能对单个主张反馈。
- 1：只能整体重新生成。

### 安全与权限透明

- 5：清楚显示使用了哪些论文、调用了什么工具、是否写入文库；高权限动作需确认。
- 3：有日志但权限说明不完整。
- 1：静默使用外部来源或修改文件。

## 6. 评测实验设计

### 样本集

- 40% 常规阅读任务：章节总结、术语解释、方法与结论抽取。
- 30% 跨文献任务：方法对照、争议归纳、研究缺口。
- 30% 难例与反例：伪造 DOI、摘要与正文矛盾、否定句、表格/脚注证据、同名作者、超长上下文、专业术语诱导。

每个任务保存输入论文版本、允许使用的来源范围、人工参考证据、不可接受的主张和预期失败类型。

### 判别力验证

为同一任务构造好、中、差三档回答：

- 好：主张级证据完整，语气与来源范围一致。
- 中：结论基本正确，但有未绑定主张或引用粒度过粗。
- 差：加入伪造引用、术语堆砌或从摘要过度推断。

检查总分与关键维度能否稳定得到 `好 > 中 > 差`，并确认“更长”不会自动得更高分。

### 一致性验证

- 两名人工评审对同一批样本独立评分，计算加权 Cohen’s kappa 或 ICC。
- LLM judge 在固定温度与固定 rubric 下重复 3–5 次，报告均值、标准差与等级翻转率。
- 自动评分与人工评分计算 Spearman 相关，并对分歧 case 归因。

### 对抗性验证

专门测试伪造引用、真实但不相关的引用、堆砌专业术语、重复内容拉长篇幅、把相关性升级为因果、隐藏来源范围等攻击。

## 7. 技术路线

当前目录是 React + TypeScript + Vite 的可交互前端原型，使用内置样例数据，尚未集成桌面数据库、真实 PDF 解析或 Hy3 API。

正式实现建议分层：

1. 内置文献核心：在同一桌面应用内管理条目、附件、集合、标签、标注、笔记、全文索引与同步状态；不要求安装 Zotero。
2. 文档证据层：集成 Reader 与 document-worker，统一 `itemKey + annotationKey + page + quote + offsets`。
3. AI 编排层：用 OpenAI 兼容接口调用 Hy3，API 地址与密钥由环境变量提供。
4. 评测层：规则校验负责元数据和锚点，LLM judge 负责语义支持，人工界面处理边界 case。
5. 审计层：记录模型、参数、输入来源、工具调用、生成主张与用户纠错。

基于 Zotero 源码构建和分发独立桌面软件前需要处理 AGPLv3 与 Zotero 商标规则。Zen 桌面仓库采用 MPL-2.0；社区主题还可能使用更严格许可，因此当前原型只提取官方信息架构、状态交互与设计变量，以原创代码实现，不复制 Zen 商标、受限图标或社区主题源码。
